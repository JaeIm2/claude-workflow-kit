# issue-writer — 어떤 업무 관리 도구든 잘 정리된 이슈로

[English](README.md) | 한국어

요청, 메모, 버그 설명을 받아 잘 구조화된 이슈 하나로 만들어주는 Claude Code 스킬. 확인 가능한 완료 조건이 있는 기능·작업 이슈나, 재현 절차와 기대 결과가 있는 버그 리포트를 쓴다.
요청이 모호하면 추측하지 않고, 작업할 수 있을 만큼 명확해질 때까지 한 번에 하나씩 질문한다.

## 필요한 것
- Claude Code
- (선택) 업무 관리 도구의 MCP 서버나 커넥터 (Jira, Linear, GitHub Issues, Notion, Asana, YouTrack 등). 있으면 중복 이슈를 확인하고 승인 후 직접 등록한다. 없으면 복사해서 쓸 수 있는 초안을 준다

## 설치
1. Claude Code에서 아래 두 줄 실행 (자세한 설치 방법은 [루트 README](../../../../README.ko.md))
   ```
   /plugin marketplace add JaeIm2/claude-workflow-kit
   /plugin install everyday@claude-workflow-kit
   ```
2. `/everyday:issue-writer`와 함께 요청을 입력하거나, 그냥 "이거 티켓 만들어줘"라고 말하면 된다
3. 첫 실행 때 몇 가지를 물어본다.
   - 업무를 어디서 관리하는지 (이 키트의 다른 스킬에서 이미 답했으면 건너뜀)
   - 이슈를 어떤 언어로 쓸지 (대화하는 언어와 달라도 됨)
   - 이슈를 주로 등록하는 프로젝트
   - 팀에서 필수로 채우는 필드나 정해진 템플릿 (예시 이슈를 붙여넣어도 됨)

설정은 `~/.claude/workflow/config.md`에 저장되고, 이 키트의 다른 스킬과 같이 쓴다. 바꾸고 싶으면 `/everyday:issue-writer 설정`.

## 쓰는 법
- "태스크 써줘: 인보이스를 PDF로 내려받을 수 있게" — 범위와 완료 조건을 확인한 뒤 초안 작성
- "버그 등록해줘: 프로필 페이지에서 저장 버튼이 안 먹어" + 스크린샷 — 빠진 내용(재현 절차, 기대 결과)을 물어본 뒤 초안 작성
- 동료가 보낸 모호한 요청 붙여넣기 — 작업인지 버그인지 판단하고, 확인한 뒤 초안 작성
- "등록은 하지 말고 초안까지만" — 초안에서 멈춤

초안은 이렇게 나온다.
- 제목은 영역 접두어 하나로 시작한다. 예: `[Billing/Invoices] Download invoice as PDF from the invoice list`
- 완료 조건이나 기대 결과는 체크박스로, 항목마다 테스트하는 사람이 눈으로 확인할 수 있는 결과 하나
- 이슈 언어가 대화 언어와 다르면 번역본을 같이 보여준다

초안은 그대로 복사할 수 있게 일반 코드 블록으로 보여준다. 초안을 승인하기 전에는 업무 관리 도구에 아무것도 등록하지 않는다.
