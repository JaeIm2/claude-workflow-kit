# plan-doc — 바로 개발에 들어갈 수 있는 기획서

[English](README.md) | 한국어

새 기능, 또는 이미 있는 제품에 기능을 추가할 때 기획서를 써주는 Claude Code 스킬.
지금 제품이 어떻게 구성돼 있는지 보고, 비슷한 제품들이 같은 기능을 어떻게 다루는지 조사한 뒤, 2~3개 안을 비교해서 하나를 추천하고 단계별로 나눈다. 받은 날 바로 개발과 검수를 시작할 수 있는 수준이 목표다.

- **화면마다 상태 체크리스트**: 정상, 빈 상태, 로딩, 오류, 권한 없음, 모바일, 접근성, 다국어. "적절히 처리" 같은 칸은 남기지 않는다.
- **검수(QA) 시나리오**를 화면 명세 바로 아래에 같이 쓴다.
- **정해지지 않은 건 추측하지 않는다.** "미정"으로 표시하고 누가 정해야 하는지 적은 뒤, 문서 끝 표에 모아둔다.

개발자가 아니어도 쓸 수 있다. 코드 레포가 있으면 더 정확하지만, 제품 주소·스크린샷·글로 된 설명만으로도 된다.

## 필요한 것
- Claude Code
- (선택) 웹 검색 — 비슷한 제품 조사용
- (선택) 브라우저 도구 (예: Playwright MCP) — 운영 중인 제품을 직접 둘러볼 때
- (선택) 문서 도구 커넥터 (구글 문서, Notion, Confluence 등) — 마크다운 파일 대신 그쪽에 문서를 만들고 싶을 때

## 설치
1. Claude Code에서 아래 두 줄 실행 (자세한 설치 방법은 [루트 README](../../../../README.ko.md))
   ```
   /plugin marketplace add JaeIm2/claude-workflow-kit
   /plugin install everyday@claude-workflow-kit
   ```
2. `/everyday:plan-doc` 뒤에 기획할 내용을 적어서 입력
3. 첫 실행 때 물어보는 것
   - 문서를 어디에 저장할지 (기본 `~/Documents/plans/`)
   - 어떤 형태로 받을지 (마크다운 파일, 또는 쓰는 문서 도구)
   - 팀에서 쓰는 기획서 양식이 있는지
   - 문서를 어떤 언어로 쓰는지

설정은 `~/.claude/workflow/config.md`의 `## plan-doc`에 저장되고, 이 키트의 다른 스킬과 같이 쓴다. 바꾸고 싶으면 `/everyday:plan-doc 설정`.

## 쓰는 법
- `/everyday:plan-doc 관리자 콘솔에 일괄 내보내기 기능 추가` — 빠진 것만 물어본다: 제품이 어디 있는지(레포·주소·스크린샷), 참고 자료, 최종 결정은 누가 하는지
- "기획서 피드백 반영해줘" + 의견 — 피드백을 반영해 다시 쓰고, 사용자가 정한 내용은 해당 "미정" 항목을 대체한다

끝나면 파일 경로, 추천안 3줄 요약, 결정할 사람별로 묶은 "미정" 목록을 받는다.
온라인 문서 도구에 문서를 만들거나 누군가에게 보내는 일은 승인한 뒤에만 한다.
