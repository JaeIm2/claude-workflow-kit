# ui-work — 만들기 전에 확인, 브라우저로 검증, 교정은 기억

[English](README.md) | 한국어

화면·컴포넌트·다이얼로그·UX 흐름을 만들거나 고칠 때 쓰는 Claude Code 스킬.
레포의 UI 컨벤션을 따르고, 코드 쓰기 전에 구조를 확인받고, 끝났다고 말하기 전에 실제 브라우저로 결과를 확인한다. 사용자가 교정한 내용은 바로 컨벤션 파일에 적어서 같은 교정을 두 번 할 일이 없게 한다.

**언제 쓰나:** 화면·컴포넌트·다이얼로그·UX 흐름을 만들거나 고칠 때, 또는 Claude가 만든 UI를 교정할 때.

**이렇게 말해보기:**
- "설정 페이지에 삭제 확인 다이얼로그 추가해줘"
- "이 화면 만들어줘" + Figma 링크나 스크린샷
- "여긴 모달 말고 토스트지"

**준비물:** 결과 확인용 브라우저 도구 (예: Playwright MCP). 없어도 동작하지만 확인 못 한 부분을 알려준다.

## 필요한 것
- Claude Code
- 자가검증용 브라우저 자동화 도구 (예: Playwright MCP — `claude mcp add playwright -- npx @playwright/mcp@latest`). 없어도 동작하지만 확인하지 못한 부분을 알려준다
- (선택) 디자인이 Figma에 있다면 Figma MCP 서버

## 설치
1. Claude Code에서 아래 두 줄 실행 (자세한 설치 방법은 [루트 README](../../../../README.ko.md))
   ```
   /plugin marketplace add JaeIm2/claude-workflow-kit
   /plugin install dev@claude-workflow-kit
   ```
2. 레포에서 UI 작업을 요청하거나 `/dev:ui-work` 입력
3. 레포마다 처음 한 번, 코드를 살펴본 뒤 몇 가지를 확인받는다.
   - 로컬에서 앱을 띄우는 명령과 주소
   - UI 컨벤션 파일 위치 (기본: 레포의 `.claude/ui-conventions.md`)
   - 번역 파일을 직접 고치는지, 외부 번역 서비스에서 관리하는지
   - 화면 확인할 때 로그인 방법 (비밀번호는 저장하지 않음)

설정은 `~/.claude/workflow/config.md`의 `## ui-work`에 저장되고, 이 키트의 다른 스킬과 같이 쓴다. 바꾸고 싶으면 `/dev:ui-work 설정`.

## 하는 일
1. **컨벤션 읽기.** 레포에 없으면 코드를 조사해서 (컴포넌트 라이브러리, 스타일 방식, 간격·타이포 토큰, 기존 화면의 로딩·빈·오류 상태 처리) 규칙마다 근거 파일을 단 컨벤션 초안을 만들고 확인받는다.
2. **디자인 확인.** Figma 링크나 스크린샷이 있으면 읽는다.
3. **구조 확인.** 코드 쓰기 전에 3~5줄로: 어디에 넣는지, 뭘 재사용하는지, 성공·실패 때 뭐가 보이는지, 엣지 케이스. 해석이 갈리면 하나를 고르지 않고 둘 다 보여준다.
4. **구현.** 컨벤션을 따르고, 요청에 필요한 부분만 고친다.
5. **브라우저로 검증.** 화면을 열어 조작하고 상태별로 확인하고, 극단 데이터(긴 이름, 넓은 표, 좁은 화면)로 넘침·겹침을 수치로 잰 뒤, 브라우저를 닫고 스크린샷을 지운다.
6. **보고.** 만든 것과 확인한 것을 알리고, 임의로 정한 부분은 표시해서 쉽게 뒤집을 수 있게 한다.

결과를 교정하면 ("여긴 모달 말고 토스트지") 그 규칙이 바로 컨벤션 파일에 들어간다.

## 쓰는 법
- "설정 페이지에 삭제 확인 다이얼로그 추가해줘"
- `/dev:ui-work` + Figma 링크나 스크린샷
- "그건 토스트 말고 인라인으로" — 고치고 규칙으로 적어둔다
