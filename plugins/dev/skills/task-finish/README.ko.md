# task-finish — 작업 마무리: 배포 확인 후에만 QA로 넘기기

[English](README.md) | 한국어

코드 작업이 끝났을 때 쓰는 Claude Code 스킬. 최신 기본 브랜치로 rebase하고, 검사를 돌리고, 커밋하고, push하고 (승인 후에만), PR(MR)을 초안 작성 후 올리고, 자동 리뷰 코멘트를 선별하고, 변경이 테스트 환경에 실제로 배포됐는지 확인한 다음에야 QA 이관을 제안한다. 머지 후에는 워크트리와 브랜치를 정리한다.
`/dev:task-start`의 반대쪽 끝.

**언제 쓰나:** 코드 작업이 끝났고, push부터 리뷰, 테스트 환경 배포, QA 전달까지 마무리하고 싶을 때.

**이렇게 말해보기:**
- "push 준비됐어"
- "PR 올리자"
- "이거 마무리하자"

**준비물:** git. 코드 저장소 서비스 CLI·MCP와 업무 관리 도구 연결은 선택.

## 필요한 것
- Claude Code, git
- (선택) 코드 저장소 서비스의 CLI(`gh`, `glab`)나 MCP 서버. 없으면 링크와 PR 초안 문구를 건네준다
- (선택) 업무 관리 도구의 MCP 서버나 커넥터. 이관 때 상태 변경에 쓴다

## 설치
1. Claude Code에서 아래 두 줄 실행 (자세한 설치 방법은 [루트 README](../../../../README.ko.md))
   ```
   /plugin marketplace add JaeIm2/claude-workflow-kit
   /plugin install dev@claude-workflow-kit
   ```
2. 작업이 끝나면 `/dev:task-finish` 입력, 또는 "push 준비됐어"라고 말하기
3. 설정이 비어 있으면 `/dev:task-start`와 같은 질문을 한다 (빠진 것만). 바꾸고 싶으면 `/dev:task-start 설정`.

## 쓰는 법
- `/dev:task-finish`, "push 준비됐어", "PR 올리자", "이거 마무리하자"

지키는 규칙:
- push 전에 검사가 전부 통과해야 한다. 기본 브랜치에서도 실패하는 검사는 보고만 하고, 마음대로 건너뛰지 않는다
- 커밋 전에는 항상 빌드
- push는 명시적으로 승인했을 때만, 작업 하나씩. "알아서 해줘"는 승인이 아니다
- push 직전에 upstream을 한 번 더 확인하고, 기본 브랜치로는 절대 push하지 않는다
- 선택 실행 파이프라인 잡(AI 리뷰 등)은 수동으로 돌리지 않고, 봇 리뷰 코멘트는 전부 적용하지 않고 선별한다
- **머지되고 테스트 환경에 배포된 걸 확인하기 전에는 QA나 리뷰를 요청하지 않는다.** 확인 방법은 설정에 적어둔 대로
- PR 생성, 업무 관리 도구 상태 변경, 댓글은 초안을 먼저 보여주고 승인한 뒤에만 실행한다

진행 상황, PR 링크, 남은 후속 작업은 그 작업의 기록(`notes/<작업>.md`)과 `todo.md`에 남는다. `/everyday:wsid`와 같은 기록을 쓴다.
