# task-start — 작업 시작: 깨끗하게 분리된 브랜치에서 착수

[English](README.md) | 한국어

새 작업을 받았을 때 쓰는 Claude Code 스킬. 업무 관리 도구에서 항목을 읽고, 먼저 끝나야 하는 작업이 있는지 확인하고, 새 브랜치를 만든다 (워크트리를 쓰면 별도 워크트리에). 그 브랜치가 실수로 기본 브랜치에 push되지 않도록 확인하고, 다음 세션이 이어받을 수 있게 작업 기록을 연다.
개발자용 스킬 3종 중 첫 번째. `/dev:task-start` → `/dev:task-finish`, QA에서 반려되면 `/dev:qa-reject`.

**언제 쓰나:** 새 작업이나 티켓을 받았고, 손으로 세팅하지 않고 깨끗한 브랜치에서 시작하고 싶을 때.

**이렇게 말해보기:**
- "PROJ-123 시작하자"
- "이 티켓 할당받음"
- "PROJ-123 ㄱㄱ"
- `/dev:task-start PROJ-123`

**준비물:** git. 업무 관리 도구 연결은 선택 (없으면 작업 내용을 붙여넣으면 된다).

## 필요한 것
- Claude Code, git
- (선택) 업무 관리 도구의 MCP 서버나 커넥터 (Jira, Linear, GitHub Issues, GitLab Issues, YouTrack 등). 없으면 작업 내용을 붙여넣으면 된다
- (선택) 코드 저장소 서비스의 CLI(`gh`, `glab`)나 MCP 서버. task-finish에서 쓴다

## 설치
1. Claude Code에서 아래 두 줄 실행 (자세한 설치 방법은 [루트 README](../../../../README.ko.md))
   ```
   /plugin marketplace add JaeIm2/claude-workflow-kit
   /plugin install dev@claude-workflow-kit
   ```
2. `/dev:task-start PROJ-123` 입력 (본인 항목 번호로)
3. 첫 실행 때 몇 가지를 물어본다. 레포에서 알아낼 수 있는 건 먼저 제안한다.
   - 업무를 어디서 관리하는지, 어떤 레포에서 일하는지 (이 키트의 다른 스킬이 이미 물었으면 생략)
   - 코드 저장소 서비스, 워크트리 사용 여부, 업무 관리 도구의 상태 이름
   - 레포별: 기본 브랜치, 브랜치 이름 규칙, 커밋 메시지 규칙, 검사·빌드 명령, 로컬 실행 방법, PR(MR) 올리고 머지하는 방식, 테스트 환경 배포 확인 방법

설정은 `~/.claude/workflow/config.md`의 `## dev` 섹션에 저장되고, 개발자용 스킬 3종과 이 키트의 다른 스킬이 같이 쓴다. 바꾸고 싶으면 `/dev:task-start 설정`.

## 쓰는 법
- `/dev:task-start PROJ-123`, "PROJ-123 시작하자", "이 티켓 할당받음"
- 그 작업의 기록이 이미 있으면 처음부터 다시 하지 않고 기록의 다음 할 일부터 이어간다

지키는 규칙:
- 항상 최신 기본 브랜치에서 새 브랜치를 만든다. 기본 브랜치에서 직접 작업하지 않는다
- 브랜치를 만든 직후 `git branch -vv`로 확인하고, upstream이 기본 브랜치로 잡혀 있으면 바로 해제한다 (그대로 두면 `git push` 한 번에 기본 브랜치로 들어간다)
- 워크트리를 쓰면 작업은 워크트리에서 한다. 다른 세션이 같이 보고 있는 원래 체크아웃은 건드리지 않는다
- 업무 관리 도구의 상태 변경은 먼저 제안하고, 승인한 뒤에만 바꾼다

작업 기록은 `notes/<작업>.md`에, 할 일 목록 `todo.md`에는 한 줄로 남는다. `/everyday:wsid`와 같은 기록을 쓴다.
